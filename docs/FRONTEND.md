## 1. Shape of the thing

The site is **one static HTML file**. There is no framework, no bundler, no
build step for the browser and no transpilation. `scripts/build_site.py`
substitutes one JSON payload into one template and writes the result.

That is a deliberate constraint, not a limitation someone failed to remove. A
page with no build system can be opened, read and audited by anyone, and it
will still render in ten years. It also means every figure on the page is
precomputed: nothing is queried at page load, so any page can be reproduced
exactly from the archived release for its run.

| File | Role |
|---|---|
| `site_src/template.html` | The entire front end: markup, styles and script in one file. |
| `site_src/counties-albers-10m.json` | County and state geometry (us-atlas, ISC licence). |
| `site_src/supabase.json` | Public project URL and publishable key for sign-in. |
| `site_src/img/` | Logo, favicon, portrait and poster images. |
| `scripts/build_site.py` | Reads an export, builds the payload, writes the page. |

## 2. The data object

`build_site.py` turns the export's CSV files into a single JSON object that the
page reads as `D`. Each key is one view's worth of data, already shaped for
display, so the browser does no joining or aggregation.

Entities in the run described here: 32.

A new field therefore has to be added in two places: exported by
`scripts/nwgs_app_export.py`, then mapped into `D` by `build_site.py`. The data
reference lists every entity and column.

## 3. Views

Each view is a function on the `RENDER` object that writes into its own
`<section id="v-...">`. Views render on first visit and are cached after that;
a resize past a threshold clears the cache so charts are redrawn at the new
width.

| Key | Label |
|---|---|
| `start` | Start here |
| `dashboard` | Dashboard |
| `map` | Surveillance map |
| `analytics` | Trends & timing |
| `leadtime` | Lead time |
| `predictive` | Predictive models |
| `monitoring` | Where monitoring happens |
| `equity` | Coverage & equity |
| `global` | Global coverage |
| `tennessee` | Tennessee |
| `genomics` | Genomics & AMR |
| `structures` | Protein structures |
| `alerts` | Alerts |
| `myalerts` | My alerts |
| `audit` | Audit log |
| `methods` | Methods & sources |
| `glossary` | Glossary |
| `about` | About the developer |

**Adding a view** means four changes in `template.html`: an entry in `VIEWS`,
a `<section class="view" id="v-yourkey" hidden>` container, a `yourkey()`
function on `RENDER`, and whatever data it needs added to `D`.

## 4. Chart helpers

Charts are drawn with d3 directly. These helpers exist so that every chart on
the site shares behaviour and theme colours.

| Helper | What it does |
|---|---|
| `countyMap(el, colorOf, tipOf, opts)` | County choropleth. `opts.filter` limits to a subset, `opts.fit` zooms to it, `opts.onClick` selects. |
| `stateMap(el, colorOf, tipOf)` | State choropleth. |
| `lineChart(el, series, opts)` | Multi-series time series. `series` take `{name, color, values:[[Date, value]]}`. |
| `spark(el, values, color, opts)` | Inline sparkline. |
| `hbars(el, rows, opts)` | Horizontal bars. `rows` take `{label, v, color}`. |
| `groupedBars(el, groups, keys, colors, opts)` | Grouped bars. Non-finite values are drawn as `n/a` rather than as a bar. |
| `donut(el, frac, slices, opts)` | Ring with a centred percentage. |
| `legend(items)` | Swatch legend. |
| `notLoaded(what, source, detail)` | The empty state. Names the source and the mechanism of its absence. |

**`notLoaded` is not decoration.** Whenever a layer has no data, the panel must
say which source did not load and why. An empty panel that explains itself is
the difference between a missing measurement and a missing source, and the two
mean entirely different things to a reader.

## 5. Theme and colour

Colours are CSS custom properties on `:root`, redefined for dark mode under
both `@media (prefers-color-scheme: dark)` and `:root[data-theme="dark"]`.
Charts read them through `css('--token')` at draw time rather than hardcoding
hex values, which is why they stay legible when the theme changes.

| Tokens | Used for |
|---|---|
| `--navy`, `--rose`, `--rose-deep`, `--teal` | Brand palette: navy carries text, rose marks the selected state and accents, teal pairs with rose on charts. |
| `--ink`, `--muted`, `--line`, `--surface`, `--bg` | Text, rules and backgrounds. `--muted` matches `--ink`: no text on the site is grey. |
| `--vl`, `--lo`, `--typ`, `--el`, `--hi` | Activity levels, Very Low through High, running teal to rose. |
| `--ok`, `--warn`, `--nodata` | Status colours. |
| `--display`, `--body`, `--mono` | Inter for the interface, IBM Plex Mono for technical strings. |
| `--sp-1` to `--sp-5`, `--card-pad` | The spacing scale cards and sections share. |

Type is three sizes and no more: 32px page titles, 20px section headings and
16px for anything written to be read, with 15px for captions and 12px for
field labels. A component that sets its own size is a bug, not a style.

Each pathogen has one colour, defined once in `PCOL` and used on its card, its
sparkline, its line on the national trend chart, its map and its chips. A
colour identifies the pathogen; it never signals severity.

A chart that hardcodes a hex value will be invisible on one of the two themes.
This has happened and been fixed; prefer `css('--token')`.

## 6. Layout

A white header holds the wordmark and six navigation groups covering all the
views above. The groups are presentation only: every view key, hash and route
is unchanged by the grouping, and a view missing from every group is appended
to a `More` group with a console warning rather than becoming unreachable.
Below roughly 760px the header collapses to a menu button and the groups
become one stacked list, so no view is more than one tap away.

Content sits in a twelve-column grid (`.grid` with `.c3` to `.c12`) with
`align-items:start`, so a short panel does not stretch to its neighbour's
height. Where that leaves a visible gap, the fix is to rebalance the row
rather than to stretch the panels: a tall panel is usually better given its
own full-width row.

Wide tables carry `class="stack"`, which collapses them into labelled blocks
below roughly 760px using each cell's `data-l` attribute as its label.

Two traps worth knowing. `all:unset` resets `box-sizing` to `content-box`,
which defeats the global `border-box` rule and makes `width:100%` plus padding
overflow its container, so anything using it restores `box-sizing` explicitly.
And a grid item spanning rows stretches those rows to its own height, so a
side-by-side block that must not do that uses flex with its own wrapper.

## 7. Runtime dependencies

| Dependency | Version | Origin | Used for |
|---|---|---|---|
| 3dmol | `2.4.0` | cdn.jsdelivr.net | Protein viewer, loaded on demand |
| supabase-js | `2.45.4` | cdn.jsdelivr.net | Sign-in and saved alerts |
| d3 | `7.8.5` | cdnjs.cloudflare.com | Charts and maps |
| topojson | `3.0.2` | cdnjs.cloudflare.com | County and state geometry |
| Structure files | - | files.rcsb.org | mmCIF/PDB, fetched when a structure is opened |
| Web fonts | - | fonts.googleapis.com | Typography; the page degrades gracefully without them |

If every one of these failed, the data, tables and text would still render.
Only charts, maps, sign-in and the 3D viewer would be affected.

## 8. Checking a change

Build the page from a known export and open it. The checks worth running on
anything that touches layout or rendering:

- every view renders with no console errors, in light and dark, at desktop and
  phone widths
- no `NaN`, `undefined` or `[object Object]` appears in any rendered view
- no element overflows its container
- figures on the page still match the export they came from
