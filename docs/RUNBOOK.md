# NWGS Grid - Runbook

The procedures: running, fixing, extending and reproducing.

**Run described:** `run_20261009T1509Z` · **Data through:** 2026-10-10 · **Generated:** 2026-10-15

> Generated by `scripts/build_docs.py` from the repository and from the export
> for the run named above. Counts, column lists, dependency versions and
> database tables are read from the code and the data rather than written by
> hand, so this document cannot drift away from what it describes.

---

## 1. Publish this week's data

The workflow runs itself on its schedule. To publish on demand, open the
repository's **Actions** tab, choose **Weekly NWGS Grid update**, and press
**Run workflow**. It takes roughly eighteen minutes, most of it in the pipeline
step.

The site changes only when the `deploy` job finishes, which is a separate job
below `build`. A green `build` alone has not updated anything.

**Push before you run.** The runner checks out what is on GitHub, not what is
on your computer.

---

## 2. Read a run that failed

1. Open the failed run and find the first red step. Steps after a failure are
   skipped, so only the first one matters.
2. Download the run artifact. It is attached even when the run fails, and it
   contains the full pipeline log and whatever tables were produced.
3. If the failure was in **Export app data**, the validation gate stopped it.
   Nothing was published and the previous week is still live, which is the
   intended behaviour.

### 2.1 Failures seen before, and what they meant

| Symptom | Cause |
|---|---|
| `HTTP 403` creating the release | Repository workflow permissions set to read-only. Settings, Actions, General, Workflow permissions, Read and write. |
| A source reported `FAILED` with a read timeout | Transient. The fetch retries, and the next run usually succeeds. |
| A panel is empty on the site | A source did not load. The Audit log names which and why. |
| Figures look right but a denominator is implausible | A parser selected the wrong column from a multi-column source. Check the candidate list in the log before trusting the gradient. |

## 3. Rotate a secret

Settings, Secrets and variables, Actions. Update the value in place, keeping
the name identical, then run the workflow to confirm the step that uses it
still passes. Secrets are never stored anywhere else, so nothing else needs
changing.

---

## 4. Add a pathogen

1. Add the CDC dataset identifier to the pipeline's configuration.
2. Add any column aliases the new dataset needs to the harmonisation table; the
   mapping actually used is written out per pathogen, so check it in the log.
3. Decide whether the pathogen is concentration-based or detection-based. The
   two take different paths through summarisation and display.
4. Export the new rows, map them into the site payload, and add them to the
   view that should show them.
5. Run and read the Audit log before publishing.

---

## 5. Reproduce a published figure

1. Note the run identifier and data-through date in the site header, or in the
   heading of any generated document.
2. Open the release tagged with that run identifier.
3. Download `<run_id>_app_export.zip` for the entity CSVs, or
   `<run_id>_tables.zip` for the full pipeline tables.
4. Rebuild the page: `python3 scripts/build_site.py <export_dir> site`

Re-running the pipeline will **not** reproduce an old run, because it always
pulls current data and CDC revises its datasets. The release is the
reproducible artifact, not the code path.

---

## 6. Regenerate the documentation

```
python3 scripts/build_audit_doc.py <export_dir> docs/DASHBOARD_AUDIT.md
python3 scripts/build_docs.py      <export_dir>
node scripts/md_to_docx.js docs/<NAME>.md docs/<NAME>.docx
```

`<export_dir>` is a run's app export: the folder holding `manifest.json` and
the entity CSVs. The Word converter needs the `docx` package once:
`npm install docx`.

---

## 7. Before publishing a change to the page

- Build from a known export and open every view.
- Check light and dark, desktop and phone.
- Confirm no view shows `NaN`, `undefined` or `[object Object]`.
- Confirm the figures on the page still match the export.
- If a layer can be empty, confirm its empty state names the source and the
  reason, rather than showing nothing.
